- **04b**: 이정표, 갈림길, 문서 마무리 (커밋 2)

04b도 `04b`로 바꿔 같은 방식으로 시작한다.

## eple이 원하는 것 (원문 요약)
- 빈터와 오두막을 둘러싸고, 처음과 끝이 이어지는 **원형 길**을 만든다. 산길 초입에서 시작한다.
- 원형 길을 걸으면 **바깥 숲을 보며 계속 걸을 수 있다.** "숲만 걷기" 같은 이정표가 필요하다.
- 원 안쪽: **빈터**는 지금보다 **왼쪽**으로 옮기고, 거리는 **4/5 정도**로 줄인다. **오두막**은 **살짝 오른쪽**으로 옮긴다.
- 길이 구불거리는 정도는 **지금이 딱 좋다.** 바꾸지 않는다.
- 원형 길에서 **"숲의 빈터" 이정표**를 만나면 빈터로, **"오두막" 이정표**를 만나면 오두막으로 갈 수 있다.

## 04a 단계

### 1. 배치안을 먼저 eple에게 확인받는다 (코드 수정 전)
아래 내용을 **글로 된 위에서 본 배치도**(좌표 표 + 간단한 ASCII 그림)로 보여 주고 승인을 받는다.
- 지금 좌표: 초입 `(0, 72)`, 빈터 `(0, -62)`, 오두막 `(0, -152)`
- 해석안(확인 필요):
  - "거리 4/5" = 초입에서 빈터까지의 거리 134 → 약 107. 왼쪽(-x)으로 옮긴다. 예: 빈터 `(-30, -30)` 근처
  - 오두막은 지금 자리에서 오른쪽(+x)으로 조금. 예: `(+12, -150)`
  - 원형 길: 초입 근처에서 갈라져 빈터와 오두막 바깥을 크게 한 바퀴 돌아 초입으로 돌아온다. 이동 가능 범위(`x ±86`, `z -225 ~ 105`) 안쪽 5m 이상에 둔다.
  - 초입 → 빈터 → 오두막으로 가는 지금의 안쪽 길은 남긴다.
- eple이 숫자를 고쳐 주면 그 숫자를 따른다. 확정된 좌표를 PROGRESS.md에 적는다. 05 지도 묶음에서 쓴다.

### 2. 오두막을 옮길 때 주의
- `world.ts`에 **절대 좌표**로 적힌 오두막 가구와 충돌 상자가 많다. 예: `fireplace: { x: -4.9, z: -152.4 }`, 충돌 상자 `x0: -5, x1: -4.1, z0: -153.9`.
- 숫자를 하나씩 고치지 말고, `CABIN.x`, `CABIN.z` 기준의 **상대 좌표**로 바꿔 한 번에 옮긴다. 바꾼 뒤 오두막 1층·2층·계단·벽난로·침대 위치가 그대로인지 확인한다.
- `Cabin.tsx`도 같은 기준을 쓰는지 grep(`-152`, `-147`, `-157`)으로 확인한다.

### 3. 원형 길
- 지금 길 곡선을 만드는 방식(점 목록, 곡선 등)을 그대로 쓰고, 구불거림의 크기와 주기도 지금 값을 그대로 쓴다.
- 나무, 바위, 버섯이 새 길 위에 생기지 않게 기존의 "길 피하기" 처리에 새 길을 넣는다.
- 바닥 높이와 발소리 바닥 종류(`surface`)가 새 길에서도 "길"로 나오게 한다.

## 04b 단계

### 4. 이정표와 갈림길
- 원형 길과 안쪽 길이 만나는 곳마다 이정표를 세운다.
  - 초입: `← 숲만 걷기 (한 바퀴)` / `숲의 빈터 →`
  - 원형 길에서 빈터로 가는 갈림길: `숲의 빈터`
  - 원형 길에서 오두막으로 가는 갈림길: `오두막`
- 갈림길에서 원 안쪽으로 짧은 길을 이어 빈터와 오두막에 실제로 닿게 한다.
- 이정표는 빈터 "쉬어가는 곳" 표지판과 같은 스타일 코드를 쓴다.
- 존(zone) 판정에 원형 길을 추가해 "지금 있는 곳" 표시가 `숲길 한 바퀴`처럼 나오게 한다(지금 존 표시 방식을 따른다).
